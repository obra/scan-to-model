# Reusable work packets

A work packet is the brief for a useful outcome inside the existing project, not another queue or evidence hierarchy. Use one brief for a coherent room boundary, connection or assembly. Put related source checks, build attempts and review results beneath it. A local lookup can be answered directly in the active brief or returned to root; it does not need its own milestone.

## Shared brief

```text
Outcome: <physical change or specific decision needed by the active build>
Role: <source examiner, geometry builder, reviewer, or records worker>
Accepted dependencies: <current scoped source/geometry dispositions and limits to carry forward>
Inputs: <exact relevant source/model/selection paths and retained hash bindings>
Work: <what to inspect or construct, affected interfaces, and allowed changes>
Return: <usable geometry or the decision, evidence links, review result and remaining limits>
Stop: <evidence sufficient to build, a named unresolved fact, or only a paused runtime remaining>
Outputs: <active increment directory; fresh subdirectories for retained executions>
```

Link existing accepted records instead of copying their contents into every brief. Root resolves the current authority once, including an exact selected artifact or JSON field when an older narrative differs. Workers carry that scope and its limits forward. Discovery briefs bind a starting source set; they need not name undiscovered frames before searching. Follow [evidence-workflow.md](evidence-workflow.md) for retention at execution boundaries.

## Root: choose, decide and finish

Select from the current package priorities and accepted checkpoint. Subtract delivered geometry once for the affected region. Choose a coherent physical outcome large enough to improve the model, then resolve source interpretation and interfaces needed to build it. Several surfaces of the same opening usually belong to one candidate. Do not select work merely because a small face is easy to measure or a records audit is ready.

Give mechanical workers precise inputs and outputs; retain physical judgment, priority and acceptance at root. Use the project's chosen worker model when specified. An independent source lane is useful only when it answers a named next modeling question or delivers separately requested historical work. Root should build or decide while workers execute, rather than serially authoring new review packets for their handoffs.

A worker's claim that a prerequisite is missing is a finding to inspect, not a new gate. Follow the supplied path and selector before searching older reports. Resolve ambiguity once at root and return the corrected binding in the active brief. If a worker produces a coordinate or topology error, fix the responsible producer or use the maintained helper, check the affected result, and continue the same increment. Do not restart source identity or registration because the implementation was wrong.

Reopen a settled investigation only when new evidence, an owner correction, a demonstrated current-model conflict or a changed required use could change its disposition. Name that change before dispatch. If the specified sources cannot answer the question, retain the no-result and choose another supported outcome. Pending measurement or runtime constraints remain explicit; repeated qualification is not a new deliverable.

## Source examiner

Open the named originals and return the physical facts needed by the build: feature identity including side/face, visible boundaries, endpoint meaning and uncertainty. Compare new face coverage with accepted images before calling a view redundant. Keep source examination separate from depth support and placement. For an exhausted selection, return the exact missing fact and any specifically different source that could resolve it; do not launch a general archive audit.

Use [source-observe](../skills/source-observe/SKILL.md) for annotated construction inventories and [depth-inspect](../skills/depth-inspect/SKILL.md) for native measurements. The pixel/frame conventions and retention commands are in [formats.md](formats.md). Resolve room/level membership from the explicit feature and accepted records in [project-records.md](project-records.md). A filename, page direction or collection name is only a discovery hint. Failed tools leave the scope unexamined, not absent.

## Geometry builder

Build the complete supported increment using the accepted coordinate frame and dimensions. Inspect adjoining saved geometry first; a new surface that overlaps an existing lining or leaves an unaddressed casing conflict is not a completed connection. Return the proposed reconciliation within the authorized change scope, or name the exact unresolved interface. Do not erase accepted work or invent hidden surfaces to make a clean join.

Reuse maintained geometry and projection helpers. Declare source and destination frames and apply the transform exactly once. When the reviewed plan supplies vertices and faces, consume them verbatim. Preserve architecture, contents, finishes, historical construction and services as separate categories. Return candidate identity, changed objects, source bindings and the relevant saved-geometry/visual checks together.

Use [blender-reconstruct](../skills/blender-reconstruct/SKILL.md) and [blender-review.md](blender-review.md) for native construction and preservation. For manufactured parts use [manufactured-shapes.md](manufactured-shapes.md). For offline preparations, record that native presence and contact review are pending. Once a coherent batch is ready for a paused runtime, retain the exact next command and stop that batch.

## Reviewer

Review the declared outcome against the retained inputs, current accepted dependencies, changed geometry and affected interfaces. Use fresh outputs for review executions and preserve the original candidate and failed evidence. Return pass, bounded pass or fail with actionable findings and the remaining physical limits. A valid receipt proves execution identity; inspect the actual geometry and depicted pixels for physical acceptance. Do not silently repair or promote a candidate while reviewing it.

Check unrelated content with the native inventory comparison. Additions must match the declared allowlist; undeclared changes/removals fail. Source, transform, material or view changes determine which checks need repeating. Reuse a matching baseline inventory and settled reviews of unchanged dependencies. After a correction, repeat affected checks and the final preservation comparison; do not replay every earlier source analysis or rerender unaffected deliverables. See [blender-review.md](blender-review.md) for the exact native contracts.

## Records and tool work

At increment closeout, update the existing geometry/evidence ledger, active package and affected drawing links once. Link the retained execution receipts and carry physical limits forward. Keep investigation completion separate from integrated geometry. A records worker may perform this mechanical update from root's disposition; it must not independently change acceptance. Use [project-records.md](project-records.md) and the project's existing synchronization tools when those records actually change.

Improve a tool for a demonstrated defect or repeated mechanical operation needed by the current build. Validate that behavior and return to the build. Publish reusable mechanics and stable interpretation rules under the project's authorization; keep private source paths, addresses, scans and owner observations outside the plugin. Avoid turning each failed attempt into another mandatory process rule.
